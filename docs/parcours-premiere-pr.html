Ta première pull request

De « dossier vide » à « PR fusionnée », voici le parcours complet réalisé ensemble. Chaque étape : ce qui s'est passé, la commande réelle, et ce qu'elle produit.

01

Connecter la machine à GitHub

une seule fois
  1. 01

    Créer le compte GitHub

    Fait dans le navigateur, sur github.com/signup. Ton identifiant public : coachpolebasketpicardie-boop.

  2. 02

    Installer et connecter gh (le CLI GitHub)

    Le binaire a été posé dans ~/.local/bin et ajouté au PATH. Puis gh auth login ouvre le navigateur pour autoriser ta machine.

    $ gh auth login
    ? GitHub.com · HTTPS · Login with a web browser
    ! First copy your one-time code: AB12-CD34
    ✓ Logged in as coachpolebasketpicardie-boop
  3. 03

    Régler ton identité Git

    Chaque commit est signé d'un nom et d'un email. On a utilisé l'adresse « noreply » de GitHub pour ne pas exposer ton vrai email dans l'historique public.

    $ git config --global user.name "Coach.dude"
    $ git config --global user.email "322569028+coachpolebasketpicardie-boop@users.noreply.github.com"
02

Poser le projet

le point de départ
  1. 04

    Créer les fichiers

    Un mini-projet Python : basket_stats.py (3 fonctions de stats), test_basket_stats.py (6 tests), README.md, et .gitignore qui exclut le dossier .venv/.

  2. 05

    Lancer les tests

    On vérifie que tout marche avant d'enregistrer quoi que ce soit.

    $ pytest -q
    ...... [100%]
    6 passed in 0.02s
  3. 06

    Initialiser le dépôt Git

    git init crée le dossier caché .git/ : à partir de là, Git suit l'historique du projet.

    $ git init
  4. 07

    Premier commit

    git add . sélectionne les fichiers, git commit fige la première « photo » du projet, sur la branche master.

    $ git add .
    $ git commit -m "Projet initial : fonctions de stats basket + tests"
    [master (root-commit) d811edd] 4 files changed, 91 insertions(+)
  5. 08

    Créer le dépôt sur GitHub et pousser

    Une seule commande crée le dépôt distant, le relie sous le nom origin, et envoie master.

    $ gh repo create basket-stats --private --source=. --remote=origin --push
    ✓ Created repository coachpolebasketpicardie-boop/basket-stats on GitHub
    ✓ Pushed commits to https://github.com/…/basket-stats.git
03

Le cycle d'une pull request

à répéter à chaque changement
  1. 09

    Créer une branche

    On travaille à côté, sans toucher à master. Tant que rien n'est fusionné, la version « officielle » reste intacte.

    $ git checkout -b ajout-test-lancers-francs-zero
    Switched to a new branch 'ajout-test-lancers-francs-zero'
  2. 10

    Faire la modification, puis revérifier

    Ajout d'un test : test_free_throw_pct_aucun_lancer (+4 lignes dans le fichier de tests, aucun code de production touché). On relance pytest.

    $ pytest -q
    7 passed in 0.02s
  3. 11

    Enregistrer le changement (commit)

    Une nouvelle « photo », sur la branche cette fois.

    $ git commit -am "Ajoute un test pour free_throw_pct sans lancer tenté"
    [ajout-test-lancers-francs-zero 5bd5710] 1 file changed, 4 insertions(+)
  4. 12

    Pousser la branche sur GitHub

    La branche existe maintenant aussi côté distant. GitHub propose déjà un lien pour ouvrir la PR.

    $ git push -u origin ajout-test-lancers-francs-zero
    * [new branch] ajout-test-lancers-francs-zero -> ajout-test-lancers-francs-zero
  5. 13

    Ouvrir la pull request

    « Voici ma branche ajout-test-…, comparez-la à master et intégrez-la. » GitHub affiche le diff ligne par ligne.

    $ gh pr create --base master --title "…" --body "…"
    https://github.com/coachpolebasketpicardie-boop/basket-stats/pull/1
  6. 14

    Relire et fusionner

    Sur GitHub : onglet Files changed pour voir les 4 lignes vertes, puis bouton Merge pull request. Un commit de merge est créé sur master.

    Merge pull request #1 … fcdb96d
    ✓ Merged · state: MERGED
  7. 15

    Remettre le local à jour et nettoyer

    On récupère le merge dans le master local, puis on supprime la branche des deux côtés : elle a fait son travail.

    $ git checkout master && git pull
    $ git push origin --delete ajout-test-lancers-francs-zero && git fetch --prune
    - [deleted] ajout-test-lancers-francs-zero

L'historique, tel que Git le dessine

C'est ce qu'affiche git log --graph --oneline. On lit de bas en haut : le projet, puis la branche qui part sur le côté, puis le point où elle rejoint master.

*   fcdb96d  (HEAD -> master, origin/master)  Merge pull request #1
|\  
| * 5bd5710  Ajoute un test pour free_throw_pct sans lancer tenté
|/  
*   d811edd  Projet initial : fonctions de stats basket + tests

Les 6 mots

dépôt
Le dossier du projet plus tout son historique. Local sur ta machine, et une copie sur GitHub (origin).
commit
Une modification enregistrée, avec un message et un identifiant court (d811edd). Une photo datée et légendée.
branche
Une ligne de travail parallèle. On y fait ses changements sans risque pour master.
push
Envoyer ses commits locaux vers GitHub. Rien n'arrive en ligne tant qu'on n'a pas poussé.
pull request
Une proposition d'intégrer une branche. GitHub montre le diff et sert de lieu de relecture.
merge
Intégrer la branche dans master. Le changement devient « officiel ».

Et maintenant

Le geste est toujours le même. Pour la PR #2, on recommence à l'étape 09 : une branche, un commit, un push, une PR, un merge, un nettoyage.

Première commande : git checkout -b exemple-dans-le-readme

branche → commit → push → pull request → merge → nettoyage
